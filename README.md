# Expense Tracker

A calm, local-first expense tracker for iOS and Android. No accounts, no backend,
no analytics. Everything is stored on the device.

## Setup

Requires Flutter 3.24 or newer (Dart 3.5+).

This archive contains the app source (`lib/`, `test/`, `pubspec.yaml`). Flutter's
native platform folders are generated by the SDK itself, so that they always match
your installed Flutter version. Generate them once, then run:

```sh
cd expense_tracker
flutter create --platforms=android,ios --project-name expense_tracker --org com.example .
rm -f test/widget_test.dart   # sample test generated by flutter create; it does not apply here
flutter pub get
flutter run
```

`flutter create .` never overwrites `lib/main.dart` or `pubspec.yaml`.
Change `--org` to your own reverse-domain identifier if you plan to ship the app.

Useful commands:

```sh
flutter analyze
flutter test
```

## Features

- Add, edit and delete expenses (amount, category, date, optional note)
- Home: total spent this month and recent transactions grouped by day
- Filters by date range and category, shown as removable chips
- Insights: month switcher, total, comparison with the previous month, daily
  average, category breakdown, and a six-month history
- Settings: currency, theme (Light / Dark / System), clear all data
- Empty, loading and error states; confirmation before every destructive action;
  inline validation with specific messages

## Decisions

**State management: Provider.** Three small `ChangeNotifier`s (settings, expenses)
cover the whole app. Riverpod would add ceremony without a benefit at this size.

**Storage: sqflite for expenses, shared_preferences for settings.** Expenses are
structured, dated records that need ordering, range filtering and safe deletes, which
suits SQLite. Hive would need generated adapters; Isar is no longer actively
maintained. Two preference values (theme, currency) do not justify a database, so
they use shared_preferences. The controller keeps the full list in memory (a personal
ledger stays small) and writes through to SQLite.

**Money is stored as integer minor units** (cents, or whole yen for JPY), never as
floating point, so sums are exact. Dates are stored as `yyyy-MM-dd` text, which sorts
and filters correctly and is unaffected by time zones or daylight saving.

**Currency selector changes display only.** Existing amounts are not converted. The
Settings screen says so.

**Expenses only.** The brief asks for expense tracking, so there is no income entry.
The semantic colours are used sparingly: the "expense" colour marks a month that cost
more than the last, "positive" marks one that cost less, and "danger" is reserved for
destructive actions and errors.

**Categories are fixed.** Eight built-in categories keep the breakdown readable. A
category is stored by name, and unknown names fall back to "Other".

**Font: platform default** (SF on iOS, Roboto on Android). It needs no bundled asset,
renders crisply, and respects the user's system settings. Amounts use tabular figures
so columns line up.

**Future dates are not allowed** when adding or editing.

## Design system

All visual decisions live in `lib/core/theme/`:

| File | Purpose |
| --- | --- |
| `tokens.dart` | Spacing (4/8/12/16/24/32), radii (8/10/12), sizes, type scale, and the two hand-tuned colour palettes |
| `app_colors.dart` | `ThemeExtension` for semantic colours that are not in `ColorScheme` |
| `app_theme.dart` | Builds the light and dark `ThemeData` and all component themes |

Widgets read from the theme and tokens; no colours, sizes or font styles are hardcoded
in feature code.

- **Type:** display 36, title 20/16, body 16/14, caption 12, in three weights (400, 500, 600).
- **Colour:** off-white and near-black neutrals, one muted green accent used for the
  primary action and selection. Dark mode uses `#0E0E10` with raised surfaces stepping
  lighter, rather than pure black.
- **Contrast:** primary and secondary text, accent-on-surface and error text were chosen
  to meet WCAG AA (4.5:1) in both themes. Bars and tiles have adjacent text labels, so
  meaning never depends on colour alone.
- **Touch targets:** buttons, icon buttons, chips, list rows and the navigation bar are
  at least 48dp. Layouts wrap or ellipsise rather than clip, so larger text sizes from
  `MediaQuery.textScaler` are respected.
- **Feedback:** subtle ink press states, light haptics on save and selection, a medium
  haptic when a destructive action is confirmed, and an animated 300 ms theme cross-fade.

## Project structure

```
lib/
  main.dart                 Entry point, opens storage
  app.dart                  Providers and MaterialApp
  core/
    theme/                  tokens, semantic colours, ThemeData
    utils/                  date helpers, formatters, validators
    widgets/                empty state, confirm dialog, snack bar, proportion bar
  data/                     SQLite and preferences repositories
  models/                   Expense, category, currency, filter, summaries
  features/
    shell/                  Bottom navigation
    home/                   Overview and transaction list
    expenses/               Controller, form, filter sheet, list items
    insights/               Monthly summary
    settings/               Preferences and data management
test/
  validators_test.dart      Parsing, formatting and model round-trip tests
```

## Error handling

Storage failures never crash the app. Repository errors become a `StorageException`
with a user-safe message. Loading errors show a retry state, failed saves and deletes
show a snackbar, and a failure to persist a preference is reported while the choice
still applies for the session.
